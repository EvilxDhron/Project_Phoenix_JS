## 1. What is a function?

A **function** is a reusable block of code that performs a task. We write the code once and can run it whenever needed.

```js
function greet() {
  console.log("Hello!");
}

greet(); // Hello!
greet(); // Hello! — the same function can be used again
```

Why use functions?

- **Reuse:** write a task once instead of repeating the same code.
- **Organisation:** break a large problem into smaller tasks.
- **Readability:** names such as `calculateTotal()` explain what a piece of code does.
- **Testing and fixing:** a small function is usually easier to check and debug.
- **Abstraction:** use a function without needing to think about every step inside it.

A function can take input, do some work, and return output. It does not have to do all three: a function can take no input, or it can perform an action without returning a useful value.

## 2. Define, call, and return

### Basic syntax

```js
function functionName(parameter1, parameter2) {
  // Code to run
  return result;
}
```

- `function` — keyword used to declare a regular function.
- `functionName` — the name used to call it.
- **Parameters** — variable names written in the function definition.
- **Function body** — code inside `{ }`.
- `return` — sends a value back to the code that called the function.
- **Call / invocation** — running a function by writing its name followed by `()`.

```js
function add(a, b) {
  return a + b;
}

const answer = add(10, 5); // call the function
console.log(answer);       // 15
```

Writing `add` refers to the function value. Writing `add()` calls the function.

```js
console.log(add);   // shows the function itself (display varies by console)
console.log(add()); // calls add with no arguments; a and b are undefined, so result is NaN
```

### `console.log()` is not the same as `return`

`console.log()` displays something in the console. `return` gives a value back to the caller.

```js
function addAndPrint(a, b) {
  console.log(a + b);
}

function addAndReturn(a, b) {
  return a + b;
}

const first = addAndPrint(2, 3);  // prints 5
console.log(first);               // undefined

const second = addAndReturn(2, 3);
console.log(second);              // 5
```

Use `return` when another part of the program needs the result. Use `console.log()` when you simply want to display something while learning or debugging.

### A function without `return`

If a function reaches its end without returning a value, JavaScript returns `undefined` automatically.

```js
function sayHi() {
  console.log("Hi");
}

const result = sayHi(); // prints Hi
console.log(result);     // undefined
```

### `return` ends the function

```js
function checkAge(age) {
  if (age < 0) {
    return "Invalid age";
  }

  return "Age accepted";
  console.log("This line never runs");
}
```

Once JavaScript executes `return`, it leaves that function immediately. A line break after `return` can cause a surprise because of automatic semicolon insertion:

```js
function getObject() {
  return
  {
    name: "Dhron"
  };
}

console.log(getObject()); // undefined
```

Keep the returned value on the same line as `return`, or use parentheses:

```js
function getObject() {
  return {
    name: "Dhron"
  };
}
```

## 3. Parameters and arguments

**Parameter:** a named placeholder in the function definition.

**Argument:** the actual value supplied when the function is called.

```js
function introduce(name, age) { // name and age are parameters
  return `My name is ${name} and I am ${age}.`;
}

introduce("Aman", 20); // "Aman" and 20 are arguments
```

### Missing and extra arguments

JavaScript does not require the exact number of arguments declared by a function.

```js
function multiply(a, b) {
  return a * b;
}

multiply(4, 3);    // 12
multiply(4);       // NaN, because b is undefined
multiply(4, 3, 9); // 12; the third argument is unused by this function
```

### Primitive values are passed by value

Changing a parameter variable does not change the caller's original primitive variable.

```js
function changeNumber(n) {
  n = 100;
}

let score = 10;
changeNumber(score);
console.log(score); // 10
```

For objects and arrays, the value passed is a reference to the same object. A function can change that object's contents, but reassigning the parameter does not reassign the caller's variable.

```js
function changeUser(user) {
  user.name = "Riya";          // changes the same object
}

const person = { name: "Aman" };
changeUser(person);
console.log(person.name); // "Riya"
```

But:

```js
function replaceUser(user) {
  user = { name: "Riya" }; // only changes the local parameter
}

const person = { name: "Aman" };
replaceUser(person);
console.log(person.name); // "Aman"
```

This is often described as **sharing an object reference by value**.

## 4. Ways to write a function

JavaScript supports several function forms. They can do similar work, but they do not all behave the same way.

### 4.1 Function declaration

```js
function subtract(a, b) {
  return a - b;
}

subtract(9, 4); // 5
```

A named function declaration is a good default for a reusable, named task.

### 4.2 Function expression

A function can be stored in a variable like any other value.

```js
const divide = function (a, b) {
  return a / b;
};

console.log(divide(10, 2)); // 5
```

The function above is anonymous because the function expression itself has no written name. It is stored in the `divide` variable.

A **named function expression** can be useful for clearer stack traces or recursion inside the function:

```js
const factorial = function calculateFactorial(n) {
  if (n <= 1) return 1;
  return n * calculateFactorial(n - 1);
};
```

Here, `calculateFactorial` is the inner function name; outside this expression, call it with `factorial()`.

### 4.3 Arrow function

Arrow functions use `=>` and are especially common for short functions and callbacks.

```js
const square = (n) => {
  return n * n;
};

console.log(square(5)); // 25
```

If the body contains only one expression, the braces and `return` can be removed. The value of the expression is returned automatically:

```js
const square = n => n * n;
const add = (a, b) => a + b;
const getMessage = () => "Hello";
```

Rules for shorter syntax:

```js
const one = x => x + 1;      // one simple parameter: parentheses may be omitted
const two = (x, y) => x + y; // multiple parameters: parentheses are required
const zero = () => 100;      // no parameters: use ()
```

To return an object literal from a short arrow function, wrap the object in parentheses:

```js
const makeUser = name => ({ name: name });
console.log(makeUser("Aman")); // { name: "Aman" }
```

Without parentheses, `{}` is treated as the function body rather than the object literal.

### 4.4 Method shorthand in an object

```js
const calculator = {
  add(a, b) {
    return a + b;
  },
  subtract(a, b) {
    return a - b;
  }
};

calculator.add(8, 2);      // 10
calculator.subtract(8, 2); // 6
```

These are methods: functions stored as properties of an object.

### 4.5 Constructor function

A regular function can be used with `new` to create objects. This older pattern is still useful for understanding JavaScript prototypes, even though modern code often uses classes.

```js
function User(name, age) {
  this.name = name;
  this.age = age;
}

const user1 = new User("Aman", 20);
console.log(user1.name); // "Aman"
```

More detail is in [Constructor functions, `new`, and prototypes](#18-constructor-functions-new-and-prototypes).

### 4.6 Generator function (extra topic)

A generator uses `function*` and `yield` to produce values one at a time when its iterator is advanced. It is not an async function, but it is a separate topic and can be studied later.

```js
function* countToThree() {
  yield 1;
  yield 2;
  yield 3;
}

const counter = countToThree();
console.log(counter.next()); // { value: 1, done: false }
console.log(counter.next()); // { value: 2, done: false }
```

### 4.7 The `Function` constructor (know it; usually avoid it)

```js
const add = new Function("a", "b", "return a + b");
console.log(add(2, 3)); // 5
```

It builds a function from strings. It is rarely the right choice in normal application code: it is harder to read, has security concerns when strings are untrusted, and does not capture local lexical variables like a normal function expression.

## 5. Arrow functions vs regular functions

Arrow functions are not just shorter syntax. Their behaviour differs from regular functions.

| Feature | Regular function | Arrow function |
|---|---|---|
| Syntax | `function (x) { ... }` | `(x) => ...` |
| Own `this` | Yes; depends on how it is called | No; takes `this` from surrounding scope |
| Own `arguments` object | Yes (except special cases) | No |
| Can be called with `new` | Ordinary constructible functions can | No |
| Has a `prototype` property for construction | Usually yes for ordinary functions | No |
| Good for object methods needing the object's `this` | Often | Usually not |
| Common use | Named tasks, methods, constructors | Short callbacks and lexical `this` |

Example of the `this` difference:

```js
const user = {
  name: "Aman",
  regularMethod: function () {
    return this.name;
  },
  arrowMethod: () => this.name
};

console.log(user.regularMethod()); // "Aman"
console.log(user.arrowMethod());   // does not use user as its this value
```

Do not use an arrow function as an object method when you expect `this` to mean that object. An arrow function is useful inside a method when you want to keep the method's existing `this`:

```js
const user = {
  name: "Aman",
  showName() {
    const print = () => console.log(this.name);
    print(); // "Aman"
  }
};

user.showName();
```

## 6. Function declaration vs function expression

```js
// Declaration
function greet() {
  return "Hello";
}

// Expression
const greetAgain = function () {
  return "Hello again";
};
```

The main difference beginners notice is **hoisting**.

```js
console.log(add(2, 3)); // 5

function add(a, b) {
  return a + b;
}
```

A function declaration is initialized before normal execution reaches its line, so it can usually be called before its written position in the same scope.

But a function expression assigned to a `const` variable cannot be called before that variable is initialized:

```js
// multiply(2, 3); // ReferenceError if uncommented here
const multiply = function (a, b) {
  return a * b;
};
```

For clean code, declare functions before the place they are used unless there is a clear reason not to.

## 7. Scope, local variables, and hoisting

**Scope** decides where a variable or function name can be accessed.

### Global scope

A global variable is declared outside functions and blocks. Avoid making every value global; global state can make a project harder to understand and maintain.

```js
const appName = "Study App";

function showAppName() {
  return appName; // can read a variable from the outer scope
}
```

### Function scope

Variables declared with `let` and `const` inside a function belong to that function (more precisely, their enclosing block where applicable) and cannot normally be used from outside.

```js
function test() {
  const message = "Inside";
  console.log(message); // Inside
}

test();
// console.log(message); // ReferenceError
```

### Block scope

`let` and `const` are limited to the `{ }` block in which they are declared.

```js
if (true) {
  const status = "ready";
}

// console.log(status); // ReferenceError
```

`var` is function-scoped rather than block-scoped, so modern JavaScript code usually prefers `const` or `let`.

### Lexical scope

A function can access variables from the scope where it was **written**, including surrounding functions. This is called lexical scoping.

```js
const language = "JavaScript";

function outer() {
  const topic = "functions";

  function inner() {
    return `${topic} in ${language}`;
  }

  return inner();
}

console.log(outer()); // "functions in JavaScript"
```

The inner function can read `topic`, but the outer function cannot directly read variables declared only inside `inner()`.

### Hoisting: keep the details straight

- Function declarations are hoisted with their function value in their scope.
- `var` declarations are hoisted and initially have the value `undefined`.
- `let` and `const` declarations are hoisted in the technical sense, but cannot be accessed before initialization. This period is called the **temporal dead zone (TDZ)**.
- A function expression follows the initialization rules of the variable used to store it.

```js
console.log(count); // undefined
var count = 5;

// console.log(total); // ReferenceError (TDZ)
let total = 5;
```

## 8. Closures

A **closure** happens when a function retains access to variables from its outer lexical scope, even after the outer function has finished running.

```js
function makeCounter() {
  let count = 0;

  return function () {
    count++;
    return count;
  };
}

const counter1 = makeCounter();
console.log(counter1()); // 1
console.log(counter1()); // 2
console.log(counter1()); // 3

const counter2 = makeCounter();
console.log(counter2()); // 1 — a separate call has its own count
```

Why is this useful?

- Keep a variable private from direct outside access.
- Remember data between function calls.
- Create configurable functions.
- Build function factories and some common design patterns.

A closure does not freeze a variable's value at the moment the function is created. It retains access to the variable itself, so later changes can be visible.

```js
function makeGreeter(name) {
  return function () {
    console.log(`Hello, ${name}`);
  };
}

const greetDhron = makeGreeter("Dhron");
greetDhron(); // Hello, Dhron
```

## 9. `this` inside a function

For regular functions, `this` is generally determined by **how the function is called**, not simply by where it was written.

### Method call

```js
const student = {
  name: "Dhron",
  showName() {
    console.log(this.name);
  }
};

student.showName(); // Dhron
```

Here, `this` refers to the object before the dot: `student`.

### Standalone call

```js
function showThis() {
  console.log(this);
}

showThis();
```

In strict mode, `this` is `undefined` for this plain call. In a non-strict classic script, it may be the global object. Avoid depending on the non-strict behaviour. JavaScript modules run in strict mode.

### `this` can be lost

```js
const student = {
  name: "Dhron",
  showName() {
    console.log(this.name);
  }
};

const show = student.showName;
// show(); // this is not student here; may print undefined or throw depending on mode
```

Use `bind()` when you need a regular function to keep a chosen `this`, or use an arrow callback where lexical `this` is appropriate.

## 10. Methods and object functions

A **method** is a function stored as an object's property and used through that object.

```js
const phone = {
  brand: "Samsung",
  ring() {
    return `${this.brand} is ringing`;
  }
};

console.log(phone.ring()); // Samsung is ringing
```

A method can be assigned after the object is created:

```js
const phone = { brand: "Samsung" };
phone.ring = function () {
  return `${this.brand} is ringing`;
};
```

A property holding a function is not automatically required to be written using method shorthand. Both patterns are valid.

### Getter and setter functions

Getters and setters look like properties when used, but they run functions behind the scenes. They are often used to validate or control access to data.

```js
const account = {
  _balance: 100,

  get balance() {
    return this._balance;
  },

  set balance(value) {
    if (value >= 0) this._balance = value;
  }
};

console.log(account.balance); // 100 — no parentheses
account.balance = 250;        // calls the setter
console.log(account.balance); // 250
```

The underscore in `_balance` is a naming convention suggesting an internal property; it does not make the property truly private.

## 11. Functions are first-class values

JavaScript treats functions as values. This means a function can be:

1. Stored in a variable or object property.
2. Passed as an argument to another function.
3. Returned from another function.
4. Stored in an array.
5. Created when the program is running.

```js
function sayHello() {
  return "Hello";
}

const savedFunction = sayHello;
console.log(savedFunction()); // Hello
```

Notice that `sayHello` is assigned without parentheses. `sayHello()` would run the function immediately and assign its returned value instead.

## 12. Callbacks and higher-order functions

### Callback function

A **callback** is a function passed to another function so that the receiving function can call it.

```js
function processNumber(number, callback) {
  return callback(number);
}

function double(number) {
  return number * 2;
}

console.log(processNumber(5, double)); // 10
```

Here, `double` is the callback. We pass the function itself, not `double()`.

A callback can also be written inline:

```js
processNumber(5, function (number) {
  return number + 10;
});

processNumber(5, number => number + 10);
```

Both calls return `15`, although in this example the result is not printed or stored.

### Higher-order function

A **higher-order function** is a function that takes another function as an argument, returns a function, or does both.

```js
function runOperation(a, b, operation) {
  return operation(a, b);
}

const sum = runOperation(4, 6, (x, y) => x + y);
const product = runOperation(4, 6, (x, y) => x * y);

console.log(sum);     // 10
console.log(product); // 24
```

Callbacks and higher-order functions are important in array methods, event handlers, reusable utilities, and many JavaScript APIs.

## 13. Array methods that use functions

These methods accept callbacks. The callback's parameters usually include the current element, its index, and the original array, in that order.

```js
const numbers = [2, 4, 6];

numbers.forEach((number, index, array) => {
  console.log(number, index, array);
});
```

### `forEach()` — do something for each item

```js
const numbers = [1, 2, 3];
numbers.forEach(number => console.log(number));
```

- It is mainly used for side effects such as printing or updating something.
- It returns `undefined`.
- It is not designed to create a new array from callback results.

### `map()` — transform each item

Returns a **new array** containing each callback result.

```js
const numbers = [1, 2, 3];
const doubled = numbers.map(number => number * 2);

console.log(doubled); // [2, 4, 6]
console.log(numbers); // [1, 2, 3]
```

### `filter()` — keep matching items

Returns a new array containing items for which the callback returns a truthy value.

```js
const numbers = [1, 2, 3, 4, 5, 6];
const evenNumbers = numbers.filter(number => number % 2 === 0);

console.log(evenNumbers); // [2, 4, 6]
```

### `reduce()` — combine items into one result

The callback receives the accumulator and the current item. Providing an initial value is usually a good habit.

```js
const numbers = [10, 20, 30];
const total = numbers.reduce((accumulator, number) => {
  return accumulator + number;
}, 0);

console.log(total); // 60
```

### `find()` and `findIndex()`

```js
const numbers = [7, 12, 19, 24];

numbers.find(number => number > 15);      // 19 (first matching value)
numbers.findIndex(number => number > 15); // 2 (index of first match)
```

If there is no match, `find()` returns `undefined` and `findIndex()` returns `-1`.

### `some()` and `every()`

```js
const numbers = [2, 4, 6, 7];

const hasOddNumber = numbers.some(number => number % 2 !== 0); // true
const allPositive = numbers.every(number => number > 0);       // true
```

- `some()` is true if at least one item passes the test.
- `every()` is true only if all items pass the test.

### `sort()` — callback controls order

```js
const numbers = [40, 5, 100, 25];
numbers.sort((a, b) => a - b);
console.log(numbers); // [5, 25, 40, 100]
```

For numeric sorting, `a - b` gives ascending order and `b - a` gives descending order. Without a comparator, `sort()` compares string representations, which can produce surprising numeric results. `sort()` changes the original array.

### Quick comparison

| Method | Main job | What it returns |
|---|---|---|
| `forEach()` | Run code for each item | `undefined` |
| `map()` | Transform each item | New array |
| `filter()` | Keep matching items | New array |
| `reduce()` | Accumulate one result | The accumulated value |
| `find()` | Get first match | Matching item or `undefined` |
| `findIndex()` | Get first match's index | Index or `-1` |
| `some()` | Check whether any item matches | Boolean |
| `every()` | Check whether all items match | Boolean |
| `sort()` | Sort an array | The same array, sorted in place |

These methods do not make the function asynchronous. The callback runs as part of the array method's normal execution.

## 14. Rest parameters, spread, and `arguments`

### Rest parameters: collect arguments

Rest syntax uses `...` in a function's parameter list. It gathers the remaining arguments into a real array.

```js
function sum(...numbers) {
  return numbers.reduce((total, number) => total + number, 0);
}

console.log(sum(1, 2, 3));       // 6
console.log(sum(10, 20, 30, 40)); // 100
```

A rest parameter must be last:

```js
function logMessage(message, ...values) {
  console.log(message);
  console.log(values);
}

logMessage("Scores", 80, 90, 100);
// Scores
// [80, 90, 100]
```

### Spread syntax: expand values

Spread uses the same `...` symbol but does the opposite in a call or array literal: it expands an iterable's items.

```js
const scores = [10, 20, 30];
console.log(Math.max(...scores)); // 30

function add(a, b, c) {
  return a + b + c;
}

console.log(add(...scores)); // 60
```

**Memory trick:** rest gathers; spread expands. Their meaning depends on where `...` is used.

### The `arguments` object

Regular functions have an array-like `arguments` object containing the arguments passed to that call.

```js
function showArguments() {
  console.log(arguments.length);
  console.log(arguments[0]);
}

showArguments("red", "green", "blue"); // 3, then "red"
```

`arguments` is not a real array, so array methods such as `.map()` are not directly available on it. Arrow functions do not have their own `arguments` object. Modern code generally uses rest parameters instead:

```js
function showValues(...values) {
  console.log(values.length);
  console.log(values.map(value => String(value)));
}
```

## 15. Default parameters and destructuring parameters

### Default parameters

A default value is used when an argument is missing or explicitly `undefined`.

```js
function greet(name = "friend") {
  return `Hello, ${name}!`;
}

console.log(greet());          // Hello, friend!
console.log(greet(undefined)); // Hello, friend!
console.log(greet("Riya"));   // Hello, Riya!
console.log(greet(null));      // Hello, null! — null does not trigger the default
```

### Destructuring an object parameter

```js
function printUser({ name, age }) {
  console.log(`${name} is ${age} years old`);
}

printUser({ name: "Aman", age: 20 });
```

You can set a default for the whole object as well:

```js
function printUser({ name = "Guest", age = 0 } = {}) {
  console.log(name, age);
}

printUser(); // Guest 0
```

Without `= {}`, calling `printUser()` would fail because JavaScript could not destructure properties from `undefined`.

### Destructuring an array parameter

```js
function firstAndSecond([first, second]) {
  return `${first} and ${second}`;
}

console.log(firstAndSecond(["HTML", "CSS"])); // HTML and CSS
```

## 16. The `call()`, `apply()`, and `bind()` methods

These methods come from `Function.prototype`. They let you control the `this` value for a regular function.

```js
function introduce(city, country) {
  return `${this.name} lives in ${city}, ${country}.`;
}

const person = { name: "Dhron" };
```

### `call()` — call now; pass arguments one by one

```js
console.log(introduce.call(person, "Noida", "India"));
// Dhron lives in Noida, India.
```

### `apply()` — call now; pass arguments as an array (or array-like value)

```js
console.log(introduce.apply(person, ["Noida", "India"]));
// Dhron lives in Noida, India.
```

### `bind()` — create a new function for later

```js
const introduceDhron = introduce.bind(person, "Noida");
console.log(introduceDhron("India"));
// Dhron lives in Noida, India.
```

`bind()` does not run the original function immediately. It returns a new function with `this` fixed to the supplied value. It can also preset some arguments (partial application).

| Method | Runs the function immediately? | How arguments are supplied | Main purpose |
|---|---|---|---|
| `call()` | Yes | Individually | Call with a chosen `this` |
| `apply()` | Yes | As an array-like value | Same idea as `call()` with a list of arguments |
| `bind()` | No | Individually; can preset some | Make a new function with a chosen `this` |

Modern spread syntax often provides an alternative to `apply()`:

```js
const values = [4, 9, 2];
Math.max(...values); // 9
```

Important: arrow functions do not have their own `this`, so `call()`, `apply()`, and `bind()` cannot replace an arrow function's lexical `this` value.

## 17. Useful function properties and other methods

Functions are objects, so functions can have properties. These are some useful ones.

### `name`

Returns the function's name as a string.

```js
function greet() {}
const sayHello = function () {};
const arrow = () => {};

console.log(greet.name);    // "greet"
console.log(sayHello.name); // usually "sayHello" (inferred from the variable name)
console.log(arrow.name);    // usually "arrow"
```

Do not rely on inferred names for program logic; use names mainly for debugging and inspection.

### `length`

Returns the number of formal parameters before the first parameter with a default value, not the number of arguments received in a particular call.

```js
function example(a, b, c = 10, d) {}
console.log(example.length); // 2
```

### `prototype`

Most ordinary functions that can be used as constructors have a `prototype` property. Objects created with `new` can inherit methods from it. Arrow functions do not have a constructor `prototype` property.

```js
function Animal(name) {
  this.name = name;
}

Animal.prototype.speak = function () {
  return `${this.name} makes a sound`;
};

const dog = new Animal("Dog");
console.log(dog.speak()); // Dog makes a sound
```

### `toString()`

`Function.prototype.toString()` returns a source-text representation of a function. It is mainly useful for inspection, not for changing or executing function logic.

```js
function add(a, b) {
  return a + b;
}

console.log(add.toString());
```

### `new.target`

Inside a regular function, `new.target` can tell whether the function was invoked using `new`.

```js
function User(name) {
  if (!new.target) {
    throw new Error("Use new: new User(name)");
  }
  this.name = name;
}

const user = new User("Aman");
```

This is an extra constructor detail. In normal beginner code, simply remember to use `new` when calling a constructor function.

Avoid old, deprecated function properties such as `function.caller` and `function.arguments`; they are not suitable for normal modern code.

## 18. Constructor functions, `new`, and prototypes

A constructor function is a regular function intended to create and initialize objects when called with `new`.

```js
function Student(name, course) {
  this.name = name;
  this.course = course;
}

const student1 = new Student("Aman", "BCA");
const student2 = new Student("Riya", "BCA");

console.log(student1.name); // Aman
console.log(student2.name); // Riya
```

By convention, constructor function names start with a capital letter.

When `new Student(...)` runs, JavaScript roughly:

1. Creates a new empty object.
2. Links that object to `Student.prototype`.
3. Calls `Student` with `this` set to the new object.
4. Returns the new object, unless the constructor explicitly returns another object.

### Adding a shared method with `prototype`

```js
function Student(name) {
  this.name = name;
}

Student.prototype.introduce = function () {
  return `I am ${this.name}`;
};

const student1 = new Student("Aman");
const student2 = new Student("Riya");

console.log(student1.introduce()); // I am Aman
console.log(student2.introduce()); // I am Riya
```

The method is shared through the prototype rather than being recreated as a separate own method each time.

**Important:** calling a constructor without `new` can produce incorrect behaviour or an error. Arrow functions cannot be used as constructors.

## 19. Functions inside classes

Class methods are functions defined on a class's prototype. The `constructor()` method sets up each new instance.

```js
class Student {
  constructor(name, course) {
    this.name = name;
    this.course = course;
  }

  introduce() {
    return `I am ${this.name}, studying ${this.course}.`;
  }
}

const student = new Student("Dhron", "BCA");
console.log(student.introduce());
```

- `constructor()` runs when `new Student(...)` creates an instance.
- `introduce()` is an instance method.
- Call instance methods on an instance: `student.introduce()`.
- Class method syntax does not use the `function` keyword.

A class is not itself a function declaration in the same sense as the old constructor pattern, but a class's methods are still function objects and follow many of the same rules about parameters, returns, and `this`.

## 20. IIFE — immediately invoked function expression

An IIFE is a function expression that is defined and called immediately.

```js
(function () {
  const message = "This runs immediately";
  console.log(message);
})();
```

An arrow-function IIFE is also possible:

```js
(() => {
  const temporaryValue = 10;
  console.log(temporaryValue);
})();
```

IIFEs were commonly used to create a private scope before modern module systems became common. You may see them in older code, but they are not needed for every small task today.

## 21. Nested functions and returning functions

A function can be written inside another function. The inner function can use the outer function's variables.

```js
function calculate(a, b) {
  function add() {
    return a + b;
  }

  return add();
}

console.log(calculate(3, 7)); // 10
```

A function can also return another function:

```js
function makeMultiplier(multiplier) {
  return function (number) {
    return number * multiplier;
  };
}

const double = makeMultiplier(2);
const triple = makeMultiplier(3);

console.log(double(5)); // 10
console.log(triple(5)); // 15
```

This combines **higher-order functions** and **closures**.

### Function composition

Composition means passing the result of one function into another.

```js
const double = number => number * 2;
const addFive = number => number + 5;

const result = addFive(double(10));
console.log(result); // 25
```

Read it from the inside out: `double(10)` gives `20`, then `addFive(20)` gives `25`.

### Currying (extra topic)

Currying turns a function that accepts several arguments at once into a sequence of functions, each taking one argument.

```js
const add = a => b => a + b;

console.log(add(2)(3)); // 5
```

This pattern becomes more useful when studying functional programming. It is not necessary for every project.

## 22. Recursion

**Recursion** is when a function calls itself to solve a smaller version of the same problem.

Every useful recursive function needs:

1. A **base case** that stops the calls.
2. A **recursive case** that moves toward that base case.

```js
function countdown(number) {
  if (number <= 0) {
    console.log("Done!"); // base case
    return;
  }

  console.log(number);
  countdown(number - 1); // recursive case
}

countdown(3); // 3, 2, 1, Done!
```

Example: factorial. The factorial of `5` is `5 × 4 × 3 × 2 × 1 = 120`.

```js
function factorial(n) {
  if (n < 0) return undefined; // a simple invalid-input guard
  if (n <= 1) return 1;        // base case
  return n * factorial(n - 1);
}

console.log(factorial(5)); // 120
```

Without a valid stopping condition, recursive calls can continue until the call stack is exhausted. For some problems, a loop is simpler and uses less call-stack space.

## 23. Pure functions and side effects

A **pure function**:

- returns the same output for the same input, and
- does not change outside state or cause an observable side effect.

```js
function square(number) {
  return number * number;
}
```

This is pure: `square(4)` always returns `16` and does not change anything outside the function.

An **impure function** may read or change outside state, print to the console, update the page, or modify an object it receives.

```js
let total = 0;

function addToTotal(number) {
  total += number; // changes outside state
  return total;
}
```

Side effects are not always bad; programs need them. The useful habit is to keep calculations separate from actions where practical. This makes code easier to test.

### Avoid unexpected mutation

```js
function addItem(items, item) {
  items.push(item); // changes the original array
}
```

If you want a new array instead:

```js
function addItem(items, item) {
  return [...items, item];
}
```

## 24. Common patterns built with functions

### Validation with early returns

```js
function isValidScore(score) {
  if (typeof score !== "number") return false;
  if (score < 0 || score > 100) return false;
  return true;
}
```

Early returns avoid deeply nested `if` statements and make conditions easier to read.

### A factory function

A factory function returns a new object instead of being called with `new`.

```js
function createBook(title, author) {
  return {
    title,
    author,
    describe() {
      return `${this.title} by ${this.author}`;
    }
  };
}

const book = createBook("Atomic Habits", "James Clear");
console.log(book.describe());
```

### Configuration through a function

```js
function formatName(firstName, lastName) {
  return `${firstName.trim()} ${lastName.trim()}`;
}

console.log(formatName(" Dhron ", "Yadav")); // Dhron Yadav
```

### Event handler (browser / DOM example)

A function can be passed to the browser to run when an event occurs. This is another common callback use.

```js
const button = document.querySelector("button");

function handleClick() {
  console.log("Button clicked");
}

button.addEventListener("click", handleClick);
```

Pass `handleClick`, not `handleClick()`. The browser needs the function to call later when the click happens. This example assumes the page has a `<button>` element.

### Function as a configuration option

```js
function calculatePrice(price, discountFunction) {
  return discountFunction(price);
}

const finalPrice = calculatePrice(1000, price => price * 0.9);
console.log(finalPrice); // 900
```

The receiving function does not need to know how the discount is calculated; it only calls the function it receives.

## 25. Built-in functions worth knowing

JavaScript already provides many functions and objects with methods. Some useful examples:

```js
Number("42");            // 42
String(42);               // "42"
Boolean(1);               // true
parseInt("25px", 10);     // 25
parseFloat("3.14");       // 3.14
isFinite(10);             // true
Number.isNaN(NaN);        // true
Math.max(4, 9, 2);        // 9
Math.round(4.6);          // 5
JSON.stringify({ a: 1 }); // '{"a":1}'
```

Notes:

- `Number()`, `String()`, and `Boolean()` convert a value to another type.
- `parseInt()` reads an integer from the start of a string; provide the radix, such as `10`, for clarity.
- `Number.isNaN()` checks specifically for the `NaN` value.
- `Math.max()` and `Math.round()` are static methods on the `Math` object.
- `JSON.stringify()` is a method that converts supported JavaScript data into JSON text.

A method is still a function, but it is accessed through an object, for example `Math.max()` or `JSON.stringify()`.

## 26. Common mistakes

### 1. Calling instead of passing a function

```js
function greet() {
  console.log("Hello");
}

// Wrong for an event callback: button.addEventListener("click", greet());
// Correct: button.addEventListener("click", greet);
```

`greet()` runs immediately. `greet` passes the function for another piece of code to call.

### 2. Forgetting to return

```js
function square(number) {
  number * number; // calculated, but not returned
}

console.log(square(4)); // undefined
```

Correct:

```js
function square(number) {
  return number * number;
}
```

### 3. Expecting `console.log()` to return the printed value

`console.log()` is for display. It does not return the value you printed in a useful way.

### 4. Using curly braces in an arrow function but forgetting `return`

```js
const double = number => {
  number * 2; // no return
};

console.log(double(4)); // undefined
```

Correct either with implicit return:

```js
const double = number => number * 2;
```

Or an explicit return:

```js
const double = number => {
  return number * 2;
};
```

### 5. Using an arrow function where an object's `this` is needed

Use method shorthand or a regular method when `this` must refer to the object.

### 6. Confusing `return` with `break`

`return` exits the current function. `break` exits a loop or `switch` statement. They are not interchangeable.

### 7. Naming variables and functions unclearly

Prefer `calculateTotal()`, `isAdult()`, `getUserName()` over names such as `work()`, `data1()`, or `abc()`.

### 8. Modifying an array/object by accident

Methods such as `push()` and `sort()` change the original array. Know whether a method mutates data or returns a new value.

### 9. Assuming a missing argument has a useful default

A missing argument becomes `undefined` unless you handle it or define a default parameter. Validate important input.

### 10. Infinite recursion

Make sure every recursive path eventually reaches a base case.
